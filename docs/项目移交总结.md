> 项目状态：**开发中（BLE 调参主线收尾阶段）**
> 当前固件版本：**v32.5**（`17feaa1`）
> 移交时间：2026-10-24

---

## 1. 项目概述

为 **BETAFPV PAVO20 Pro 穿越机幻彩灯带** 制作一块独立灯带控制板（基于 **ESP32-C3 SuperMini** 独立固件）。

**为什么不用 WLED**：WLED 无法接收飞控外部信号（灯带信号来自飞控 LED_STRIP 输出），经核验后决定采用独立固件方案。

**核心能力**：
| 能力 | 说明 |
|---|---|
| 飞控信号解码 | GPIO4 接收飞控 LED_STRIP 信号（每帧 32 颗，GPIO 中断+忙等测高方案，v16 固化） |
| 灯带驱动 | GPIO3 输出 WS2812B（默认 55 颗，可网页调） |
| 单键手势调参 | 单击=模式 / 双击=颜色 / 三击=速度 / 长按0.8s=亮度 / 长按3s=灯珠标定 |
| WiFi 热点调参 | 热点 `RGBled/12345678`，Web 设置页（模式/颜色/速度/亮度/灯数） |
| Captive Portal | 连接热点自动弹出设置页（自动跳转历史上未成功，见遗留问题） |
| 断电记忆 | 参数存 NVS |
| WiFi OTA | 双分区在线升级，失败自动回滚 |
| 手机蓝牙调参 | BLE NUS 透传（设备名 PavoLED）+ SpeedyBee App 桥接飞控 MSP（进行中） |

## 2. 硬件与接线

### 2.1 主控板：ESP32-C3 SuperMini

### 2.2 引脚分配（当前 v32.3+）

| ESP32 引脚 | 方向 | 连接 | 用途 |
|---|---|---|---|
| GPIO3 | TX | 灯带 DATA | WS2812B 灯带输出（默认 55 颗） |
| GPIO4 | RX | 飞控 T6/C06（LED_STRIP） | 飞控 LED 信号输入 |
| GPIO9 | - | 板载 BOOT | 按键；**上电按住=进下载模式（不能做长按标定）** |
| GPIO6 | TX | 飞控 A10（UART1 RX） | BLE 透传 → 飞控（MSP 命令） |
| GPIO7 | RX | 飞控 A09（UART1 TX） | 飞控 → BLE 透传（MSP 回复） |
| GPIO20/21 | - | 板载 CH340（USB 串口） | **仅 USB 日志用，禁止外接飞控**（v32.3 教训：双驱动互拉致 WiFi/BLE 异常） |
| GPIO8 | - | 板载 LED | 指示灯 |

### 2.3 飞控侧（Betaflight）

| 串口 | 引脚 | 配置 | 用途 |
|---|---|---|---|
| UART1 | TX=A09 / RX=A10 | `serial 0 1 115200 115200 0 115200` | **蓝牙调参口（接 ESP32 GPIO6/7）** |
| UART3 | TX=B10 / RX=B11 | `serial 3 131073` | ELRS 串行接收机（不可占用） |
| UART4 | TX=A00 / RX=A01 | `serial 4 64`（MSP） | **已被大疆图传占用，不可用** |
| LED_STRIP | C06（T6） | `resource LED_STRIP 1 C06` | 灯带信号 → ESP32 GPIO4 |

> ⚠️ **重要更正（v32.5 核对）**：Betaflight 的 `serial` 第二个参数是**功能位掩码**，`1` = MSP、`64` = 串行接收机(RX_SERIAL)。
> 飞控上实际配置是 **`serial 0 1 115200 115200 0 115200`，MSP 本来就是开着的，不用改**。
> 早期文档写的 `serial 0 64` 是错的——真按它改，UART1 会变成串行接收机口，MSP 反而被关掉。
> 判断依据：每个 Betaflight dump 里 USB 虚拟串口那行固定是 `serial 20 1 115200 57600 0 115200`，可见 MSP 位就是 1。
> 若要手动确认，CLI 里 `get serial` / `dump | grep serial` 看 UART1 那行即可。

### 2.4 接线图（蓝牙调参 + 灯带）

```
飞控 A10 (UART1 RX) ←── GPIO6 (ESP32 TX)
飞控 A09 (UART1 TX) ──→ GPIO7 (ESP32 RX)
飞控 T6  (LED_STRIP) ──→ GPIO4
灯带 DATA              ←── GPIO3
GND 共地（飞控 ↔ ESP32 ↔ 灯带）
```

## 3. 功能实现要点

### 3.1 飞控信号解码（v13-v16）
- 逐一验证 RMT 方案不可行（C3 RMT 通道上限 192 符号、无 DMA、长帧截断、partial_rx 缺失）
- 最终方案：GPIO4 中断 + 忙等测高，稳定解码 32 颗/帧，v16 固化（基线 `748ef74`）

### 3.2 单键手势（v16 定稿）
单击=模式 / 双击=颜色 / 三击=速度 / 长按0.8s=亮度 / 长按3s=灯珠标定；默认亮度 50%（NVS）。

### 3.3 WiFi（v21-v30）
- AP 热点：SSID `RGBled`、密码 `12345678`、CH1、最大 4 连接
- **热点自动关闭策略**：30s 无连接关闭；连接后 60s 无操作关闭
- 心跳每秒打印：`[LED]/[WiFi]/[BLE]/[MSP]/[RX]` 全状态

### 3.4 OTA（v31）
- `partitions_ota.csv` 双分区（ota_0@0x10000 / ota_1@0x1E0000 / otadata@0x3B0000）
- `/ota` 上传页 + `/api/ota` multipart 流式写入 esp_ota
- 成功 JSON + 600ms 后重启；失败 abort + 回滚；启动 PENDING_VERIFY 防回滚

### 3.5 BLE 蓝牙调参（v32 系列，主线进行中）
- NimBLE GATT NUS 透传，设备名 **PavoLED**，广播可见 MAC `84:C7:BB:FB:B1:72`
- 广播包：Flags（可发现+仅LE）+ NUS 128-bit 服务 UUID（SpeedyBee 按服务识别）
- 透传：`手机 → BLE → UART1(GPIO6) → 飞控 UART1 → 回复原路返回`
- 波特率 115200，与飞控一致
- **已打通**：手机蓝牙可见 ✅ → SpeedyBee 可发现 ✅ → BLE 连接成功 ✅ → MTU 协商 247 ✅ → 飞控 MSP 探测有回复（`probe=ok`）✅
- **v32.6 修正**：NUS 特征 UUID 曾经装反（写用 `...03`、通知用 `...02`），导致 App 写不进（心跳 `tx=0/s`）、订阅不上（`sub=0`），2 秒后自己断开（`reason=0x213` = Remote User Terminated）。现已按标准改回 `...02`=写、`...03`=通知。

## 5. 刷机与使用

### 5.1 GitHub Actions 在线编译
- 仓库：`https://github.com/jimyu0628/pavo20-led-controller`（main 分支）
- 构件：
  - `merged.bin`：USB 首刷 / 网页刷机（含 bootloader+分区+app）
  - `firmware.bin`：WiFi OTA 用

### 5.2 三种刷机方式
| 方式 | 步骤 |
|---|---|
| USB 首刷 | 按住 GPIO9 上电进下载模式 → 烧录 merged.bin |
| 网页刷机 | 连热点 RGBled → 192.168.4.1 → 固件升级页传 merged.bin |
| WiFi OTA | 连热点 → 固件升级页 → 上传 firmware.bin（失败自动回滚） |

### 5.3 常用操作
- 调参：Web 页（连热点）/ 单键手势 / SpeedyBee App（BLE，接线后）
- 灯珠标定：长按 3s（注意上电按住 GPIO9 是下载模式）
- 看调试：USB 串口（115200）或 Web 调试区（含开机日志）

## 6. 当前状态与遗留问题（移交重点）

| # | 问题 | 状态 | 处理方向 |
|---|---|---|---|
| 1 | **SpeedyBee 连接 2 秒后断开**（MSP 握手无回复） | ✅ 根因已确认，v32.6 修复待实测 | **真因：NUS 两个特征 UUID 装反**。实测日志 `mtu=247`（服务发现正常）+ `sub=0`（订阅不上）+ `tx=0/s`（写不进来）+ `probe=ok`（UART1 正常）+ `reason=0x213`（App 主动断）。原来 `...03` 注册成只写、`...02` 注册成只读+通知，App 往 `...02` 写被 ATT 拒绝、去订阅 `...03` 没有 CCCD，白等 2 秒后自己断开。v32.6 已按标准改正（`...02`=写、`...03`=通知） |
| 2 | **Captive Portal 自动跳转从未成功** | 🔶 待实机验证 | 302 已改绝对地址 `http://192.168.4.1/`，调试区有 dns 劫持状态（dns:1/0） |
| 3 | **"搜不到 WiFi 热点"（至少 3 次反馈）** | ⏸ 挂起 | 心跳全绿（ap ok）后归因射频硬件：Erase 射频校准/供电/换板，用户未回报验证 |
| 4 | 飞控接线导致 WiFi/BLE 射频异常 | ✅ 已解决 | v32.3 换 UART1（GPIO6/7）避开板载 USB 串口；待全流程实测 |
| 5 | 若 BLE 仍断：WiFi AP 与 BLE 抢单射频 | 🔍 备选怀疑项 | C3 单射频分时，AP beacon 会挤压 BLE 连接事件。可考虑 BLE 连接期间临时关 AP，或提高 coex 优先级 |

## 8. 工程约定（接手须知）

1. **git commit 标题一律用中文**（用户偏好）
2. **版本规则**：大版本=新功能，小版本=每次修正；改版本只改 `src/ota.cpp` 的 `OTA_VER`
3. **不要动**：UART3（ELRS）、UART4（大疆图传）；GPIO20/21 只给 USB 串口用

6. 调试第一现场：Web 调试区（开机日志）+ 心跳（每秒全状态 + MSP 字节计数）

## 1. 项目概述

为 **BETAFPV PAVO20 Pro 穿越机幻彩灯带** 制作一块独立灯带控制板（基于 **ESP32-C3 SuperMini** 独立固件）。

**为什么不用 WLED**：WLED 无法接收飞控外部信号（灯带信号来自飞控 LED_STRIP 输出），经核验后决定采用独立固件方案。

**核心能力**：

| 能力             | 说明                                                     |
| -------------- | ------------------------------------------------------ |
| 飞控信号解码         | GPIO4 接收飞控 LED_STRIP 信号（每帧 32 颗，GPIO 中断+忙等测高方案，v16 固化） |
| 灯带驱动           | GPIO3 输出 WS2812B（默认 55 颗，可网页调）                         |
| 单键手势调参         | 单击=模式 / 双击=颜色 / 三击=速度 / 长按0.8s=亮度 / 长按3s=灯珠标定          |
| WiFi 热点调参      | 热点 `PavoLED-XX/12345678`（XX = MAC 末字节），Web 设置页（模式/颜色/速度/亮度/灯数）           |
| Captive Portal | 连接热点自动弹出设置页（自动跳转历史上未成功，见遗留问题）                          |
| 断电记忆           | 参数存 NVS                                                |
| WiFi OTA       | 双分区在线升级，失败自动回滚                                         |
| 手机蓝牙调参         | BLE NUS 透传（设备名 PavoLED）+ SpeedyBee App 桥接飞控 MSP（进行中）   |

## 2. 硬件与接线

### 2.1 主控板：ESP32-C3 SuperMini

### 2.2 引脚分配（当前 v32.3+）

| ESP32 引脚  | 方向 | 连接                   | 用途                                                |
| --------- | -- | -------------------- | ------------------------------------------------- |
| GPIO3     | TX | 灯带 DATA              | WS2812B 灯带输出（默认 55 颗）                             |
| GPIO4     | RX | 飞控 T6/C06（LED_STRIP） | 飞控 LED 信号输入                                       |
| GPIO9     | -  | 板载 BOOT              | 按键；**上电按住=进下载模式（不能做长按标定）**                        |
| GPIO6     | TX | 飞控 A10（UART1 RX）     | BLE 透传 → 飞控（MSP 命令）                               |
| GPIO7     | RX | 飞控 A09（UART1 TX）     | 飞控 → BLE 透传（MSP 回复）                               |
| GPIO20/21 | -  | 板载 CH340（USB 串口）     | **仅 USB 日志用，禁止外接飞控**（v32.3 教训：双驱动互拉致 WiFi/BLE 异常） |
| GPIO8     | -  | 板载 LED               | 指示灯                                               |

### 2.3 飞控侧（Betaflight）

| 串口        | 引脚              | 配置                                  | 用途                         |
| --------- | --------------- | ----------------------------------- | -------------------------- |
| UART1     | TX=A09 / RX=A10 | `serial 0 1 115200 115200 0 115200` | **蓝牙调参口（接 ESP32 GPIO6/7）** |
| UART3     | TX=B10 / RX=B11 | `serial 3 131073`                   | ELRS 串行接收机（不可占用）           |
| UART4     | TX=A00 / RX=A01 | `serial 4 64`（MSP）                  | **已被大疆图传占用，不可用**           |
| LED_STRIP | C06（T6）         | `resource LED_STRIP 1 C06`          | 灯带信号 → ESP32 GPIO4         |

> ⚠️ **重要更正（v32.5 核对）**：Betaflight 的 `serial` 第二个参数是**功能位掩码**，`1` = MSP、`64` = 串行接收机(RX_SERIAL)。
> 飞控上实际配置是 **`serial 0 1 115200 115200 0 115200`，MSP 本来就是开着的，不用改**。
> 早期文档写的 `serial 0 64` 是错的——真按它改，UART1 会变成串行接收机口，MSP 反而被关掉。
> 判断依据：每个 Betaflight dump 里 USB 虚拟串口那行固定是 `serial 20 1 115200 57600 0 115200`，可见 MSP 位就是 1。
> 若要手动确认，CLI 里 `get serial` / `dump | grep serial` 看 UART1 那行即可。

### 2.4 接线图（蓝牙调参 + 灯带）

```
飞控 A10 (UART1 RX) ←── GPIO6 (ESP32 TX)
飞控 A09 (UART1 TX) ──→ GPIO7 (ESP32 RX)
飞控 T6  (LED_STRIP) ──→ GPIO4
灯带 DATA              ←── GPIO3
GND 共地（飞控 ↔ ESP32 ↔ 灯带）
```

## 3. 功能实现要点

### 3.1 飞控信号解码（v13-v16）

- 逐一验证 RMT 方案不可行（C3 RMT 通道上限 192 符号、无 DMA、长帧截断、partial_rx 缺失）
- 最终方案：GPIO4 中断 + 忙等测高，稳定解码 32 颗/帧，v16 固化（基线 `748ef74`）

### 3.2 单键手势（v16 定稿）

单击=模式 / 双击=颜色 / 三击=速度 / 长按0.8s=亮度 / 长按3s=灯珠标定；默认亮度 50%（NVS）。

### 3.3 WiFi（v21-v30）

- AP 热点：SSID `PavoLED-XX`（XX = MAC 末字节，与 BLE 名同源）、密码 `12345678`、CH1、最大 4 连接
- **无线自动关闭策略（v32.20）**：WiFi 热点 + 蓝牙**一起**在「无设备连热点 / 无 HTTP 请求 / 无蓝牙连接」连续满 **60 秒**后关闭，只留灯带功能；关掉后需重启恢复。有手机连着、页面在轮询、蓝牙在调参，任一成立就无限续期
- 心跳每秒打印：`[LED]/[WiFi]/[BLE]/[MSP]/[RX]` 全状态

### 3.4 OTA（v31）

- `partitions_ota.csv` 双分区（ota_0@0x10000 / ota_1@0x1E0000 / otadata@0x3B0000）
- `/ota` 上传页 + `/api/ota` multipart 流式写入 esp_ota
- 成功 JSON + 600ms 后重启；失败 abort + 回滚；启动 PENDING_VERIFY 防回滚

### 3.5 BLE 蓝牙调参（v32 系列，主线进行中）

- NimBLE GATT NUS 透传，设备名 **PavoLED**，广播可见 MAC `84:C7:BB:FB:B1:72`
- 广播包：Flags（可发现+仅LE）+ NUS 128-bit 服务 UUID（SpeedyBee 按服务识别）
- 透传：`手机 → BLE → UART1(GPIO6) → 飞控 UART1 → 回复原路返回`
- 波特率 115200，与飞控一致
- **已打通**：手机蓝牙可见 ✅ → SpeedyBee 可发现 ✅ → BLE 连接成功 ✅ → MTU 协商 247 ✅ → 飞控 MSP 探测有回复（`probe=ok`）✅
- **v32.6 修正**：NUS 特征 UUID 曾经装反（写用 `...03`、通知用 `...02`），导致 App 写不进（心跳 `tx=0/s`）、订阅不上（`sub=0`），2 秒后自己断开（`reason=0x213` = Remote User Terminated）。现已按标准改回 `...02`=写、`...03`=通知。

| **v32.18** | ①**设备名统一**：新建 `src/device_name.h` 定义 `DEV_NAME "PavoLED"`，`WIFI_SSID` 与 BLE 三处硬编码（`adv_start` 的 devName、`ble_svc_gap_device_name_set`、启动打印）全部改为引用它——以后改名字只改一行，不会出现 WiFi 叫一个名、蓝牙叫另一个名的情况。取值理由：机型 Pavo20 + LED；7 字符在 WiFi 列表不截断，BLE 广播主包放得下（3+4+4+9=20 / 限 31）。②**网页飞控调参卡片重写**：原来只写「首次请在有网时打开并安装」，没讲清楚一个硬事实——**连着本热点时 `app.betaflight.com` 根本打不开**，因为 DNS 劫持把所有域名指回 192.168.4.1，点按钮只会拿到错误页。现在用橙色框明确写「先断开热点、用移动数据打开、添加到主屏幕，之后才能离线开」，并把「蓝牙」提为推荐路径（不依赖联网，飞场最稳），电脑桌面版 `tcp://192.168.4.1` 保留（a21e5ff） |
| **v32.19** | **设备名加 MAC 后缀**：`src/device_name.h` 改为声明 `const char* devName(void)` + `#define DEV_NAME devName()`，新增 `src/device_name.cpp` 实现——首次调用时 `esp_read_mac(ESP_MAC_WIFI_STA)` 取末字节，拼成 `PavoLED-%02X`（如 `PavoLED-A3`），之后缓存。WiFi `WIFI_SSID`、BLE 广播名、GAP 设备名、开机打印全引用这同一个函数，所以两边永远是同一串字符。**统一用 STA MAC 而不是各自的 MAC**：C3 的 STA/AP/BLE 三个 MAC 不同，若各取各的会出现 WiFi 叫 `-A3`、蓝牙叫 `-A4`，反而更乱。配套：`wc.ap.ssid_len` 显式赋值（名字不再是编译期字面量）；网页 `@@DEVNAME@@` 占位符在 `handler_root()` 里用 `httpd_resp_send_chunk` 分三段发（不 snprintf 拼 10KB 页面，省 RAM 给 BLE）；开机信息与网页调试区都带上设备名。BLE 主包 23/31 字节，余量 8（95b10bb） |
| **v32.21** | **Web 界面整版换代（三功能区）+ 参数无级 + 关闭无线彻底重写**。①**界面**：`src/web_page.h` 独立存放新页面（约 65KB，A+ 方案：顶部「灯光/连接/设备」三个下划线标签吸顶；灯光页内五格参数标签：模式/亮度/速度/颜色/长度，五页等高不跳动；顶部 canvas 实时预演，改哪项立刻看到；底部「应用」统一上传，未改时按钮灰、改过亮琥珀点）。颜色只点选 8 色、长度带 −/+ 长按连发、另配常用档一键到位；设备页内置 OTA 面板与使用手册（7 节折叠，断网可看）。②**参数无级**：亮度从 4 档改为 0~100%（0=关灯），速度从 3 档改为 1~100 线性映射帧间隔 200~20ms；按键手势仍按固定档循环（`BRIGHT_STEPS`/`SPEED_STEPS` + `nextStep()`），NVS 新键 `bpct`/`spct`，老键 `bright1`/`speed` 自动换算兼容。`STRIP_MAX_LEDS` 64→128（原来标定上限 128、网页写 1~128，但缓冲只有 64，超出的永远不亮）。③**接口**：`/api/state` 一条给齐三页所需（新增 maxc/ssid/ip/sta/idle/up/rs/bld/fc/msp/bdiag）；`/api/set` 改 **POST 全量提交**（form-urlencoded，`httpd_query_key_value` 直接解析，不引 JSON 解析器），GET 版保留给 curl。④**关闭无线重写**（前几版「关不掉/60 秒不自动关」的真因）：顺序改成先 `esp_wifi_stop()` 再 `httpd_stop()`（原来是反的，`httpd_stop` 会等 keep-alive 连接，而网页每秒轮询 → 永久卡住）；`s_stopping` 只在关闭期间为真、结束必复位（原来置上就永不复位，poll 首行直接 return，闲置判定跟着全废）；关闭动作改由初始化时建好的常驻 `pwrTask` 靠任务通知执行（不再临时 `xTaskCreate`）；失败重试 3 次并打印三个返回码；poll 内加 20 秒看门狗；剩余秒数每 10 秒打一行。⑤删除网页「关闭 WiFi」按钮与 `/api/wifi/off` 端点 |
| **v32.20** | ①**修「网页点关闭 WiFi，热点仍在」**。真因八成在网页侧：`offWifi()` 用 `confirm()` 做二次确认，而连热点时被系统拉起的那个 captive portal 认证页（尤其华为/荣耀的 WebView）经常把原生 `confirm` 拦掉或直接返回 false，**fetch 根本没发出去**，设备当然没收到关闭指令。改成按钮两段式（第一次点变红「再点一次，确认关闭」，4 秒不点自动复原），不依赖任何原生对话框。设备侧同步加固：`wifiStopAll()` 以前不看返回码，`esp_wifi_stop()` 失败也照样打印「热点已关闭」，且 `s_stopping` 提前置位导致失败后永不重试；现在逐步打印 `httpd/ wifi_stop / wifi_deinit` 三个返回码，且关闭动作移到独立任务 `pwrOff` 里做（`httpd_stop()` 会等 keep-alive 连接收尾，放主循环会把灯带刷新卡住）。②**无线闲置 60 秒自动关闭**（用户需求）：新增 `IDLE_OFF_MS`，判定口径为「无 STA 在线 + 无 HTTP 请求 + 无 BLE 连接」连续满 60 秒 → `shutdownRequest()` → 关 WiFi 并调 `bleUartStop()` 关蓝牙，只保留灯带。新增 `bleUartActive()`（只看是否已连接，**光广播不算活跃**，否则闲置计时永远被顶住）与 `bleUartStop()`（断连接→停广播→`nimble_port_stop/deinit`）。③**顺手修了个会卡死的隐患**：`dnsTask` 里 `recvfrom` 关 WiFi 后立刻返回 -1，原来的 `if (n < 12) continue;` 会变成死循环空转吃满一个核，灯带掉帧甚至触发看门狗，现在 `n <= 0` 时会 `vTaskDelay(200ms)`（8dd33f6） |

## 5. 刷机与使用

### 5.1 GitHub Actions 在线编译

- 仓库：`https://github.com/jimyu0628/pavo20-led-controller`（main 分支）
- 构件：
  - `merged.bin`：USB 首刷 / 网页刷机（含 bootloader+分区+app）

### 5.2 三种刷机方式

| 方式       | 步骤                                           |
